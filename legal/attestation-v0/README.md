# AttestationRegistry · version 0 的两段文本

这个目录里的两个 `.txt` **不是普通说明文档，而是部署输入与链下规范文本**。部署脚本会对规范正文
计算 keccak256，并把**两个哈希**写进 `AttestationRegistry.versions[0]`；合约不存储正文。
这两个哈希一经部署就永久存在、无法替换（这正是不变量 6③ 成立的前提）。因此改这里的任何一个字节，
都会改变待部署哈希，也就改变用户应阅读并核验的法律文本版本。

| 文件 | 对应 | 内容 |
|---|---|---|
| `terms.en.txt` | `versions[0].termsHash` | TERMS —— 关于**工具本身** |
| `attestation.en.txt` | `versions[0].attestationHash` | ATTESTATION —— 关于**用户本人** |

设计理由（为什么只写事实、不下法律结论；为什么门开在 `exercise()` 而不是 `claim()`）见
[`docs/spec.zh.md`](../../docs/spec.zh.md) §5.5。

## 字节规范

**一个文件 = 一行正文 + 恰好一个结尾 LF。** UTF-8，不含 Markdown 标记。

哈希取的是去掉那个唯一结尾 LF 之后的正文：

```
hash = keccak256(bytes(文件内容去掉那个唯一的结尾 LF))
```

复算命令：

```bash
cast keccak -- "$(cat legal/attestation-v0/terms.en.txt)"
cast keccak -- "$(cat legal/attestation-v0/attestation.en.txt)"
```

**这条命令算出来的值必须与链上一致 —— 这就是整套字节规范存在的唯一理由。**
CI 里的「version 0 哈希可复算」那一步会**真的把它跑一遍**，和 forge 侧的值对一遍。
（不是靠某条 Solidity 测试：foundry 的测试跑不了外部命令，`ffi` 没开也不打算为这件事开。
Solidity 里怎么断言都只能证明 Solidity 那一半。）

### `script/VersionZero.sol` 拒绝什么

🔴 **不合规范的输入一律拒绝，不做「修正」。** 部署当场失败，不会悄悄替你改：

| 拒绝 | 为什么 |
|---|---|
| 没有结尾 LF / 多于一个结尾 LF | 让哈希与文件字节**一一对应**（`$( )` 剥掉的是结尾**所有**换行，所以这一条不是为了复算） |
| 正文里出现 `\r` | CRLF 文件的复算值与链上不同 —— 本规范收紧的起点 |
| 正文里出现任何控制字符（`< 0x20` 或 `0x7f`） | 它们进得了链上哈希，却进不了命令行。NUL 尤其糟：bash 丢掉它只警告一句，zsh 与 fish 直接截断，三者答案各不相同 |
| 正文以 UTF-8 BOM 开头 | 三个不可见字节会一起进哈希；两边其实算得一致，但**律师看到的字与被哈希的字节不是一回事** |
| 正文以 `-` 开头 | 实测 `cast keccak "$(cat …)"` 会把 `--json` 当成开关吃掉，**静默**返回 `keccak("")`，退出码 0 |
| 正文以 `0x` 开头 | `cast keccak` 会把参数按十六进制**解码**再哈希；加 `--` 也拦不住 |
| 正文为空 | — |

一段法律正文永远不会长成上面任何一种样子，所以直接拒绝最省事。

> **为什么是「拒绝」而不是「归一」。** 早先这里是「剥掉结尾任意多个 `\n` 与 `\r`」。那样
> `文本\n` 与 `文本\r\n` 会落到**同一个哈希**：定稿之后文件被编辑器存成 CRLF，
> 钉死的哈希照样能过、部署照样成功，但复算命令算出来的是**另一个值** ——
> 审核过的那份文本与部署上去的那份就此脱节，而这个工件不可逆。

### 行尾这件事有三道防线，但只有一道守在最后

| 防线 | 挡得住 | 挡不住 |
|---|---|---|
| `.gitattributes` 的 `-text` | git 检出时的行尾归一（Windows 默认会转） | 有人直接把文件存成 CRLF 提交 |
| CI 的 `test_textFilesAreExactlyOneLine` | 仓库里的文件跑偏 | 脏工作树 |
| **部署脚本自己拒绝** | **上面全部** | — |

前两道都绕得开，只有最后这道守在不可逆的那一刻 —— 所以上面那张表里的每一条都实现在
`canonicalize` 里，而不是只写在 CI 测试里。

### 定稿记录

> 对应 issue [#18](https://github.com/quiz42/index-rein/issues/18) 的两项人工决定。
> 合约部署后 version 0 的两个哈希无法替换，以下记录是这两项决定的永久存档。

1. **权威语言：英文。** version 0 只有英文文本。「我不是美国的个人或实体」这类声明面向
   全球用户，英文是唯一对全体签署者可读性均等的选择。任何其他语言的译文均为
   **非约束性参考**，不进入哈希、不放在本目录；若需多语，作为新版本（version 1+）追加 ——
   新用户签新版，**签过 version 0 的人此后永远可以只靠这一版行权**（不变量 6③），
   所以 version 0 的英文措辞是永久的。
2. **定稿依据：外部律师审阅（2026-08-26 由项目方确认并提交）。** 本目录中的两份英文正文
   是律师审阅并修改后的版本；项目方按其精确字节冻结并提交，下面两个定稿哈希即对应该版本。
   文本严格保持 `docs/spec.zh.md` §5.5 的取向：只写事实性自述（资格声明、工具性质、
   发行方保留权限的披露），不下法律结论性断言。该审阅只确认 version 0 文本的措辞与覆盖范围，
   不代表项目其余法律风险已经消除，对外文案仍不得暗示更多（`design.md` R12）。
3. **覆盖范围**与此前中文草稿一致：TERMS 六项事实（权利而非分配资格、行权销毁 MEME
   对价、可能到期归零、债权型凭证性质、无所有权/投票权/股东权利、发行方保留冻结/
   暂停/从任意地址销毁的权限）；ATTESTATION 为受限辖区资格自述（美国 + 泛化兜底）+
   非代理声明。未加入制裁条款等草稿之外的内容。
4. **部署后**核对链上 `versions(0)` 与上表两个哈希一致（部署脚本末尾已自动断言，
   `verify-deployment.sh` 亦可回链复核）。
