## 0. 一句话

**拿到 GME → 用 GME 买 MEME → 持有，每周自动累积一批看涨权证 → 周五到期前三选一：销毁 MEME 行权换走 GME、在订单簿卖掉权证、或放过让它作废。**

### 1.1 资产、动作与合约

| 对外说法 | 链上实体 | 说明 |
|---|---|---|
| 权证 / warrant / call / 窝轮 | `Warrant`（ERC-1155） | 按 `seriesId` 分系列 |
| 系列 | `seriesId = keccak256(meme, stock, expiry)` | **按项目隔离**，不跨项目通用 |
| 开系列 | `ClearingPool.openSeries()` | **仅该 MEME 在身份根里登记的金库可调**；只能开一次，行权价此后不可改。🔴 从前这里是无许可的，敞口是抢注；issue #23 裁定改用身份根之后，抢注**没有入口**了，见 [`spec.zh.md`](./spec.zh.md) §4.2 |
| 存入即铸 | `ClearingPool.depositAndMint()` | 仅该系列的金库可调；按**实际到账增量**铸造，不按请求量 —— 带税代币下两者不等 |
| 空投 / 领取 | `MerkleDistributor.claim()` | 凭 proof 领，非自动到账；**无许可**，keeper 可代提交，权证只进 leaf 指定的 `account` |
| 行权 | `ClearingPool.exercise()` | 原子三步，另有第 0 步声明校验 |
| 受益人 | `exercise(…, beneficiary)` 的第三个参数 | 🔴 声明门查**他**、MEME 从他账上扣、股票代币直达他；调用方只能是他本人或 `MerkleDistributor` |
| 一步领取并行权 | `MerkleDistributor.claimAndExercise()` | 省掉「先领取再行权」两笔交易；仅 `account` 本人可调。🔴 与 `claim()` **共写同一个 `claimed` 标志位** |
| 合规声明 | `AttestationRegistry.attest()` | **一次性**，仅行权路径需要 |
| 抵押品 | `Series.deposited` / 池内 `stockToken.balanceOf(清算池)` | 一律 **raw 单位**；拆股改的是 `uiMultiplier`，不是余额 |
| 协议库存 | 由链上证据确认属于协议角色的 MEME 余额 | 曲线、DEX 池、Portal、代币税池与 TaxProcessor 只有同时公开角色、生效 cursor 和可复算链上证据时才从归属权重排除；v1 不穿透 LP token |
| 金库 | `WarrantVault` | **每项目一个**，🔴 **不可升级**（决策 39-A3 / #58 已落地：不继承任何 Flap 基类、不走 beacon、没有 Guardian；工厂在每次发射时直接部署一只，六个参数在 `CREATE` 那一笔里定死）。能被协议 ping 唤醒并按余额差记账，每小时采离散价格样本给出严格 trailing 24 小时读数（样本不足时明确失败）；`processRevenue()` 无许可地把每批可存收入的 10% 记给发射者（决策 49，实测扣款成功才累计），其余请求池子拉走，再按存后实际余额更新基线。池子、分发合约与 creator 是金库自己的三个 immutable 目的地（由工厂在部署那一笔里填），取价 Portal 也是构造参数。`claimCreatorFee()` 无许可地把累计分成转给 creator —— 调用方改不了收款人。`openSeries()` 同样无许可，按 24 小时 TWAP × 0.8 定行权价、到期对齐到周五 21:00 UTC 且寿命 ≥7 天，样本不足就拒绝开系列，并以 24 小时窗口限制调用方可选的时刻。**对外可写入口恰好六个**：`sync`、`sampleTwap`、`openSeries`、`processRevenue`、`receive`、`claimCreatorFee`，**没有一个是权限函数**（`initialize` 随不可升级一并消失）。 |
| 身份根 | `VaultRegistry` | 写入方是一张**构造期钉死、无 setter 的 2 格名单**（`isFactory` / `factories()`）；只有名单成员能把一只 MEME 与金库成功绑定一次。mapping 并非 Solidity `immutable`，而是只有名单成员可写的唯一 `bind` 路径，成功后永久锁死；两格共用同一张表，因此「两个写入方」不等于「两次绑定机会」。 |
| 预留写入位 | `PendingLauncherSlot` | 名单第 2 格今天填的那份合约，为**未来自建发射栈**的 launcher 占位（决策 39-D）。仅部署者、写一次、永久锁死的 `setLauncher`，发 `LauncherSet` 事件；未启用前对任何调用者 `bind` 都 fail-closed。🔴 它是**诚实成本**：把一份今天还写不出来的代码提前列入信任基，代价换的是「换发射栈时不必换池子」。 |
| 发射编排层 | `WarrantLauncher` | 🔴 **发射入口**（决策 40 / #57）。一笔交易里调普通 `Portal.newTokenV6` 建币、让工厂建一只不可升级的金库、再往身份根写下这只 MEME 的唯一一条绑定。它是身份根名单的第 1 格；除 spec §14-2 尚未定值、由调用方传入的 `antiFarmerDuration` 外，经济参数固化在字节码里。无许可 —— 陌生人用它发的项目得到的是他自己那只 MEME 的金库。 |
| 金库工厂 | `WarrantVaultFactory` | 只被 `WarrantLauncher` 调用；**直接部署一只不可升级的金库**并返回它 —— 它**不碰身份根**（绑定在 launcher 那一行）。`nextVault()` 预告下一只金库的地址，launcher 拿它填发射参数的 `beneficiary`（= 税收收款人）。任何人都可触发 `WarrantVault.openSeries()`，但池子只接受身份根已登记金库作为下游调用者的那笔开系列。 |
| 清算池 | `ClearingPool` | **平台级、每链一个、不可升级** |
| 行权价 | `Series.strike` | 每系列一个，以 MEME 计价 |
| 到期 | `Series.expiry` | 每周五 21:00 UTC。⚠️ 这是产品口径，池子不解释这个值（§4.1） |
| OTC 市场 | Seaport 1.6 + 我们的链下订单簿 | 我们不托管资产；对外名称 **Warrant Market**；买方以**该系列的股票代币**支付（决策 52） |
| 发币 | **我们自己的 launcher**（内部调 `Portal.newTokenV6()`） | 走 Flap 的普通入口，**无需注册或授权**（实测：全新合约直接发币成功）。launcher 在同一笔交易里建币、建金库、写身份根 |
| 回购金库 ⏳ | `BuybackVault`（每项目一只，规划中，spec §6.7 / 决策 50） | 任何人存 MEME；按 `min(TWAP, 现价) − strike` 打折买入价内权证并同笔行权；**深度 = 注资量，不是保证退出**；LP 提股票须已签声明 |
| 常设指令 ⏳ | `StandingOrder` 卫星（规划中，spec §6.8 / 决策 51） | 用户一次性授权 + 写规则，到期前任何人可触发「价内行权 / 卖给回购金库」；池子的行权门不变 |

### 1.2 到期、门控与维护

这一半的每个动作都**无许可** —— 任何地址都能调，持有者自己也可以。这里没有专属角色，也没有管理员。

| 术语 | 链上实体 | 说明 |
|---|---|---|
| 发行方 | Robinhood：`Stock` + 中央权限注册表 `0xe10b…1b00` | 全链股票代币共用一套角色与黑名单 —— 封一次，该地址在全链所有股票代币上同时失效 |
| 门控 | `ClearingPool.gating(stockToken)` → `Gating` | 发行方状态的**观测记录**，三态：干净 / 门控中 / 读不通 |
| 观测 / poke | `ClearingPool.pokeGating()` | 🔴 **只在状态翻转时写**。「解除时刻」若能被反复推动，结算就能被永久阻止（不变量 4③，spec §7） |
| 行权截止时刻 | `ClearingPool.exerciseDeadline()` | **不等于**到期时间：门控观测中窗口无截止（但发行方仍禁转时实际行权会整笔回滚），解除后是 `max(到期, 解除时刻 + 48h)` |
| 宽限 | `ClearingPool.GRACE_PERIOD`（48 小时） | 从**观测到**解除那一刻起算，不是从发行方实际解除起算 |
| 自动延期 | **没有对应的函数** | 它是「门控中结算做不到、行权窗口保持开放」的结果，不是一个开关。解除后行权立刻可用，**不必等 poke**；观测到解除只是把窗口收敛为 `max(到期, 解除观测时刻 + 48h)` —— 不要去找 `extend()` |
| 到期结算 | `ClearingPool.settleExpired()` | 先观测一次，再要求实时无门控且已过行权截止时刻 |
| 余量 | `Series.remainder` | `deposited − exercised`，结算那一刻算定，等着滚存 |
| 滚存 | `ClearingPool.rollExpired()` | 池内重新归属，抵押品**永不出池**；无许可，六道门全部由池子自证 |
| 作废 | **没有对应的动作** | 过了行权截止时刻就用不了。权证不被销毁、仍在持有者手上；结算之后它对应的抵押品进 `remainder`，滚给还在场的人 |
| Monitor | 链下服务（[`spec.zh.md`](./spec.zh.md) §9） | 三项职责：监控发行方事件、poke 的保底触发者、每日核对**停发**。**不是信任依赖**：合约只信记录在案的观测，而任何人都能留下观测 |
| 停发 / 发行活性 | 「本周期该开的系列没开出来」（[`spec.zh.md`](./spec.zh.md) §9.1，issue #42） | 与偿付无关：偿付是结构保证，**发行活性是运营保证**。判据取链上 `Series` 记录，**不假定周五 21:00** |
| publisher | `AttestationRegistry.publisher` | 只能**追加**声明文本版本对应的两个哈希，碰不了旧版本或任何人的声明状态 |
| root publisher | `MerkleDistributor.publisher` | 每周发布归属 root 的地址。🔴 **本系统唯一的中心化信任点**：它决定这一周的权证发给谁。但它拿不走权证 —— `claim()` 只往 leaf 指定的 `account` 发货。与上一行是**两把钥匙**，可以是不同地址 |
| 归属 root | `MerkleDistributor.roots(seriesId)` / `rootFrozen(seriesId)` | 每系列一个。该系列**第一张 leaf 被领走之前**可改（纠错），之后永久冻结 |

## 2. 三个资产

### 2.1 MEME（`FlapTaxTokenV3`）【规划集成】

由 Flap 发行，**不是我们的合约**。

| 项 | 值 |
|---|---|
| 总量 | **10 亿**（Flap 平台统一，非我们可选） |
| 买入税 / 卖出税 | **3% / 3%** |
| 税收币种 | **GME 本身**（因为交易对是 MEME/GME） |
| 税收去向 | `mktBps = 10000` → 扣除 Flap 协议费与集成方 commission 后的税收余额 100% 进我们的金库 |
| 税收期限 | **100 年**（上限） |

> 🔴 **`taxDuration` 是个坑**：Flap 官方示例写的是 365 天。照抄的话，项目会在**上线一年后无声死亡**——税停 → 无股票进池 → 无权证。我们的模板锁死为上限。

**我们无法修改 MEME 合约**，这带来一个直接后果：无法在其中记录持仓时长，所以归属只能链下算（见 §5.2）。

### 2.2 GME（Robinhood Stock）【已核验】

`0x1b0E319c6A659F002271B69dB8A7df2F911c153E` · 10,773 持有人

**法律形态**：发行方发行的**追踪股价的债权型凭证**（tokenized debt security，发行方公开披露）——**不代表标的股票所有权、无投票权、无股东权利**。本文所有"股票 / GME"均指这个代币，不是股份本身。（2026-08-09 补记）

**架构**：BeaconProxy → 实现 `0xb35490d6f9163DE4F80d88dc75c3516eb64C5aE2`（合约名 `Stock`，已验证源码）。权限**外置到全链共用的中央注册表** `0xe10b6f6b275de231345c20d14ab812db62151b00`。

**发行方保留的能力**（逐条读源码确认）：

| 角色 | 能力 |
|---|---|
| `BLOCKER_ROLE` | 🔴 封禁任意地址。`onlyNotBlocked` **硬编码在 `transfer`/`transferFrom`/`approve`/`permit` 每条路径** |
| `ADMIN_BURNER_ROLE` | 🔴 **从任意地址销毁任意数量，无暂停检查、无黑名单检查** |
| `PAUSER_ROLE` / `TOKEN_PAUSER_ROLE` | 全局暂停 / 单币暂停 |
| `BEACON_UPGRADER_ROLE` | 一次性升级全部股票代币 |
| `MULTIPLIER_UPDATER_ROLE` | 改 `uiMultiplier`，支持 `effectiveAt` 预约 |
| `METADATA_UPDATER_ROLE` | 改名改代号 |

**当前实测状态（2026-08-08）**：未暂停、抽查地址未被封、从持有 14,813 GME 的地址模拟转账到陌生 EOA / `0xdead` / 1.0 GME **全部通过**。

> **机制已接线，但一项都没启用。** 这是"能力"不是"现状"——但它决定了 §12 的风险边界。

**Robinhood Chain 上的 EIP-8056**：拆股与股息复投通过 `uiMultiplier` 传导，**`balanceOf` 不变**。因此我们所有记账一律用 raw 单位，前端显示时才乘 multiplier。BEP-677 只出现在历史 BSC 对照中。

### 2.3 Warrant（ERC-1155）【已实现，未部署】

我们发行。`id = seriesId`。**同一系列内完全同质、可自由转让**——这是 Seaport 撮合与部分成交的前提。

只有 `ClearingPool` 能铸造与销毁。

## 3. 完整玩法流程

```
  ┌──────────────────────────────────────────────────────────────────┐
  │  ①拿 GME → ②买 MEME → ③持有累积 → ④领取 → ⑤周五前三选一        │
  │                          ↑                    ├─ 行权（烧 MEME）  │
  │                          └── 卖出即停止累积 ──┼─ 卖出（订单簿）   │
  │                                               └─ 放过（池内滚存） │
  └──────────────────────────────────────────────────────────────────┘
```

### ① 拿到 GME
在 Robinhood Chain 上获得 GME。**这是入场的前置条件**——不能直接用 ETH 买 MEME。

### ② 用 GME 买 MEME
曲线阶段或毕业后的 DEX 都可以。**买入付 3% 税**（曲线阶段另有 Flap 的 1% 曲线费；它不从税收里扣）。

### ③ 持有，权证自动累积
每天一次，金库把已到账的 GME 存进清算池，按 **1:1** 铸造权证。

**你的归属按该系列完整窗口的时间加权持仓计算一次**——不是快照，也不是每天按当天收入各算一次。
持有全窗才拿满，领取前一秒买入拿不到任何东西；完整窗口平均余额低于 10,000 MEME 的地址不参与分配。

### ④ 领取
每周发布一次 merkle root，你凭 proof 调 `claim()`。**任何人都可以替你提交** ——权证只会进 leaf 里写死的那个地址，所以代提交拿不走东西，keeper 可以替你付 gas。

> **领取只在你要转让/卖出时才必需**——行权可以直接从累积余额执行，不必先铸成代币。这是为了避免"忘了领取就作废"的陷阱。

### ⑤ 周五 21:00 UTC 前，三选一

| 动作 | 你付出 | 你得到 | 需签声明 |
|---|---|---|---|
| **行权** | 销毁 `strike × 数量` 的 MEME | 对应数量的 GME | **是**（一次性，见 §6.3） |
| **卖出** | 权证 | 订单簿上的溢价（GME 或 ETH） | 否 |
| **放过** | — | 无。对应股票在清算池内滚存，计入下一系列 | 否 |

## 4. 权证详解

### 4.1 系列与到期

| 项 | 值 |
|---|---|
| 到期 | **每周五 21:00 UTC**（固定，不随夏令时调整） |
| 最短寿命 | **≥7 天** —— 距最近周五 <7 天时，新铸造归入下一个周五 |
| 同时活跃系列 | **每个项目恰好 2 个**（一个累积中、一个待到期） |

**为什么固定 UTC 而不跟美股收盘**：行权**不需要结算价**（就是"烧 N 枚换 1 单位"），所以夏令时那 1 小时漂移**没有任何经济后果**，纯粹是标注问题。

### 4.2 行权价怎么定

```
strike = TWAP(前 24 小时，MEME/GME) × 0.8
```

- **每个系列只定一次**，在系列开启时锁死，整周所有铸造共用
- 以 **MEME** 计价：一张权证 = 用 `strike` 枚 MEME 换 1 单位 GME
- 开局 **价内 20%**

**为什么必须每系列一个**：税是持续到账的，一周内可能 dispatch 几十次。若每次按当时价格定 strike，同一系列里会出现几十种不同 strike 的权证——**它们不是同一个资产，ERC-1155 无法同 id 表示，订单簿直接碎掉**。

**为什么必须用 TWAP 而非现价**：strike 一周只定一次却决定整周发行量。读现价意味着**拉一次盘就能锁定一整周的行权价**。M2-2 的读数是严格 trailing 24 小时的离散 spot 聚合：攻击者必须反复控制受 65 分钟上限约束的采样段，但每次采样后可以恢复市价；它不是连续观测或累计价预言机。

### 4.3 🔑 权证的价内外，取决于 MEME 相对 GME，不是 GME 的美元价

这是整个设计最不直观、也最容易误解的性质。

设系列开启时 1 GME = 1,000 MEME，则 strike = 800 MEME。

| 一周后 | 行权划算吗 | 你的处境 |
|---|---|---|
| 1 GME = **500** MEME（你的币跑赢） | ❌ 烧 800 换价值 500 的东西 → 归零 | 但你的仓位对股票翻倍了 |
| 1 GME = 1,000 MEME（持平） | ✅ 烧 800 换 1,000 → 赚 200 | 正常 |
| 1 GME = **2,000** MEME（你的币跑输） | ✅ 烧 800 换 2,000 → 深度价内 | **恰好在你的币最弱那周补偿你** |

> **权证是"做多 GME + 做空你自己的 meme"的相对头寸。它在你的 meme 不给力时才值钱——这是一层每周免费发放的对冲。**

要让它归零，你的币得在一周内对 GME 暴涨超过 20%。真到那时候，你有更值得高兴的事。

## 5. 分发怎么跑

### 5.1 每日铸造【混合：池与 M2-3 金库路径已实现，生产调度未上线】

```
Flap TaxProcessor ──dispatch GME + ping──► WarrantVault.receive()（只记账）
                                                    │
        我们的 Trigger Service ──每日一次──► processRevenue()
                                                    │
                          ClearingPool.depositAndMint(seriesId, distributor, 余额)
                                                    │
                                   按【实际余额增量】铸造，不按预期值
```

**为什么不放在 `receive()` 里**：`receive()` 由 Flap 的 dispatch 触发。在其中做存款和铸造会显著抬高 gas，且任何 revert 都会干扰 Flap 的税收结算。

**为什么每天而不是每次**：strike 每系列固定后，频率不影响同质性，只剩成本考量。每日一次还把**在途资金**（金库已收到、尚未存入池子）的暴露窗口压到 ≤24 小时。`processRevenue()` 只在余额可读时执行；读不出来会如实回滚，不能把这次失败误当成「金库里没有钱」。

> 🔴 **最上面那条箭头的终点，是 Flap 说了算的。** Portal 上的
> `changeMarketWallet(token, newWallet)`（`TAX_GUARDIAN_ROLE` / `DEFAULT_ADMIN_ROLE`）改的是
> **税打给谁**。发币时那个地址是我们的金库；改掉之后，同一只代币的税流向别处，而**代币、金库、
> 身份根里的绑定全都原封不动**。Robinhood Chain 主网上这个权限**已经用过三次**（三次都在别人的
> 代币上，见 [`design.md`](./design.md) 决策 35）。
>
> **我们没有任何链上防御手段** —— 这是 Flap 合约上的权限。能做的只有看见：
> `script/watch-market-wallet.sh` 盯着这个事件（入口 `script/monitor.sh tax`）。🔴 2026-08-17 起它**没有调度器**，要人想起来跑 —— 见 README「守夜」一节那条残余风险。
>
> 边界见 §12：它动不了**已经铸出的权证**，也动不了**池子里的抵押品**，能改的是**此后**流进金库的税收。

### 5.2 ⚠️ 归属为什么必须链下算

**MEME 合约是 Flap 的，我们 hook 不了它的 `_update`。** 没有转账钩子，就无法用链上 accumulator 维护每个用户的记账。而"claim 时按当前余额算"会被"领取前一秒买入"直接套利。

**解法**：

```
Indexer 订阅 MEME 的 Transfer 事件
  → 重建每个地址的持仓时间序列
  → 计算区间内的时间加权持仓
  → 按比例分配本周应得权证
  → 发布 merkle root
```

| | |
|---|---|
| ✅ | 保留"只需持有、无需质押" |
| ✅ | **任何人可用公开的 Transfer 事件独立复算并验证 root**（算法与脚本开源） |
| ✅ | 时间加权而非快照，堵死"领取前买入" |
| ⚠️ | **这是本系统唯一的中心化信任点**：root 由我们计算并提交 |

**为什么不做成质押**：那会把"持有即累积"变成"质押才累积"，与核心叙事冲突。

### 5.3 你这一周拿到多少

```
你的权证 = floor(系列截止前的可分配权证总量 × 你的合格整窗权重 ÷ 全体合格整窗权重)
```

**分母只含完整窗口平均余额至少 10,000 MEME 的合格持仓**；曲线、Portal、代币自身税池、TaxProcessor、
DEX 池等可由链上证据识别的协议库存被排除，
v1 不向 LP 持有人穿透。每户独立向下取整，余数留在 Distributor；每日存入时点不会改变任何人的份额。

> 分子里的「可分配权证总量」**已经是扣掉 10% creator 分成之后的数** —— 铸造是针对每批收入进池的那 90% 计的,不是税的全额(决策 49；见 §8.1)。

## 6. 行权详解

### 6.1 原子三步

```solidity
require(!settled);   // 到期由"结算"生效；发行方门控期间结算被阻止 = 自动延期（观测到解除后截止为 max(到期, 解除观测时刻 + 48h)）
require(attestedVersion[你] != 0);                     // 0. 合规声明，见 §6.3
1. warrant.burn(你, seriesId, 数量)                    // 销毁权证
2. MEME.transferFrom(你, 0xdead, strike × 数量)        // 销毁 MEME
3. GME.transfer(你, 数量)                              // 转出股票 ← 可能失败
```

**任一步失败，整笔回滚。** 第 3 步是唯一可能因外部原因失败的——发行方冻结或暂停时。

> 这正是我们要的行为：**发行方冻结期间，你不会失去权证**。而且门控期间**到期日自动延期**，不会作废。

### 6.2 两个直接后果

**行权即通缩。** 每领走一份股票，就永久销毁一部分 MEME。

**行权制造买压。** 在订单簿上买了权证、但手里没有 MEME 的人，必须去市场买来销毁。**权证的二级市场，结构上就是 MEME 的需求通道。**

### 6.3 行权前的一次性声明【已实现，文本已定稿（英文）】

首次行权前至少签署一次链上声明（`AttestationRegistry.attest()`），此后链上门槛永久满足。重复签同一版、
或签过新版后再签旧版都允许；状态取历史最大版本，事件则记录每次签署行为。

**签的是两段文本的哈希**。规范文本保存在 [`legal/attestation-v0/`](../legal/attestation-v0/)；链上只保存哈希，前端必须在展示前逐字节复算并比对：

| 文本 | 内容 |
|---|---|
| **TERMS** | 你理解拿到的是**按价买入的权利**、行权需**销毁 MEME 作对价**、可能到期归零、标的发行方保留冻结与销毁能力 |
| **ATTESTATION** | 你声明自己不位于美国或其他限制辖区，且非代他人行事 |

**这道门只在行权路径上。** 持有、累积、领取、在订单簿卖出——**全都不需要签**。受限辖区的用户可以完整参与"持有 → 累积 → 领取 → 卖出"，只是不行权。而卖出往往还是更优的经济选择（行权等于放弃权证的时间价值）。

> 🔑 **这道门在结构上不可能锁死你。** 声明状态**只增不减**，**只有你自己能写**，任何人（包括项目方）都无法撤销；初始版本的两个哈希**永久存在于合约中**，规范文本则可从仓库独立取得并复算，你任何时候都能自行签署。链上只要求"签过至少一次"，前端要求最新版本——**即使我们的网站下线，你也能直接调合约签署并行权。**

**它不代表合规问题已解决。** 它覆盖的是"谁能收到股票"，覆盖不了"发行了期权"和"运营了期权市场"这两条更大的敞口。而且自我声明**不可强制执行**——换个地址就绕开了。**它买到的是证据与善意，不是强制力。**

## 7. OTC 市场

**v1 在 Robinhood Chain 上使用 Seaport 1.6 结算**【已核验】（`0x0000000000000068F116a894984e2DB1123eB395`，ConduitController `0x00000000F9490004C11Cef243f5400493c00Ad63`）。BSC 部署信息只属于历史调研，不是 v1 的依赖或验收项。

**模式**：卖方链下签名挂单（**零 gas**）→ 买方提交给 Seaport → 合约验签并原子交换。**货始终在卖方钱包，成交那一刻才划走。**

| 项 | 值 |
|---|---|
| 撮合 | 链下订单簿（我们运营），结算上链 |
| 挂单 / 撤单 | **零 gas** |
| 部分成交 | ✅ 支持（挂 100 张、吃 30 张） |
| **taker 费** | **前 8 周 0%，之后 0.5%** |
| **maker 费** | **永久 0** |

**为什么不用 AMM**：期权有时间价值衰减，LP 会被 theta 持续磨损，池子最终必枯。

**为什么只收 taker**：我们最缺的是挂单深度，不该向提供深度的人收费。

## 8. 经济账【规划推演，非实测】

> 以下是**带假设的算例**，用于理解量级。合约未上线，无真实数据。

**假设**：MEME 市值 $1,000,000，日成交额 $200,000（20% 换手），税率 3%/3%。

> 🔴 **下面这套算例里最不牢靠的是哪个假设，你应该知道。** 它把**全部**成交量都当成收税的。历史 BSC MarsCoin 样本显示，Flap 的税只对涉及**已注册交易对**的转账生效：平行无许可池不收税，38 分钟样本中 **70.4% 的成交量在那里，实际税捕获率 0.90%，名义为 3%**（【已核验】，[`research/flap-tax-and-burn-path.md`](./research/flap-tax-and-burn-path.md)）。这不是 Robinhood Chain 的验收证据；v1 仍保留目标链收税阳性对照与平行池对照。
>
> **下面每一个数字都请读作「发生在收税场所的那部分成交量」。** 这一点我们的合约修不了 —— MEME 合约是 Flap 的。
>
> 🔴 **issue #58 永久移除了 Flap 金库模板路径，也一并移除了那笔 0.06% 的模板方 commission。** 现在只剩 0.06% 的集成方 commission；Flap 的 1% 曲线费是曲线阶段单独收取的费用，不是下表 3% 交易税里的扣项。

### 8.1 一天的钱怎么分

| 项 | 金额 | 去向 |
|---|---|---|
| 交易税（3%） | $6,000 | 以 GME 形式收取 |
| − Flap 协议费（≤0.3% 交易量） | −$600 | Flap |
| − 集成方 commission（0.06%） | −$120 | 我们 |
| = 税收余额到账金库（交易量的 2.64%） | $5,280 | 金库 |
| − creator 分成（可存批次的 10%，决策 49） | −$528 | 发射者 |
| **= 进池铸造权证（交易量的 2.376%）** | **$4,752** | **持有者** |

**权证拿到税的约 79%,发射者拿约 9%**(决策 49 —— 在金库里累计,由发射者无许可地 `claimCreatorFee` 拉走)。平台侧唯一的自动化收入是 0.06% 的集成方 commission = $120/天;这 10% 分成**不是平台收入**,它进的是发射者、不是我们。

### 8.2 持有者视角

持有 1%（$10,000）的人：

| | |
|---|---|
| 一周入池 GME（扣掉 10% creator 分成后） | $4,752 × 7 = **$33,264** |
| 你的份额（1%） | 覆盖 **$332.64** 的 GME |
| 行权需销毁 MEME | $332.64 × 0.8 = **$266.11** |
| **净得** | **$66.53 / 周**（≈ 仓位的 **0.67%**） |

### 8.3 为什么撸不到羊毛

狙击者在铸造前买入、之后卖出：

| | |
|---|---|
| 来回税成本（$10,000 仓位） | 3% + 3% = **$600** |
| 单日累积的权证内在价值（扣分成后的入池基数） | $4,752 × 1% × 20% ≈ **$9.50** |
| **差距** | **63 倍** |

要让单日累积盖过 6% 的来回成本，**日成交量需持续超过市值的 12 倍**。

> **给机制供血的税，同时也是保护它的东西。**

### 8.4 巨鲸

权证按持仓比例分配，大户拿得多——任何分红都是同一套算术。**区别在于他能拿它做什么：**

- 行权 → 必须销毁**成比例的大量 MEME**，同时缩减自己的仓位与流通供应
- 砸权证 → 给小持有者一个**折价买入股票的入口**

两条路都会把一部分价值还给其他人。而一个直接收到股票、转头去别处卖掉的巨鲸，不会。

## 9. ⚠️ 规则陷阱清单

按踩坑代价排序。

1. **🔴 周五 21:00 UTC 一到，未行权的权证作废。** 对应股票在清算池内滚入下一系列、重发给还在场的人——**你的那份不会退给你**。两周不管 = 两周的累积全丢。（例外：发行方冻结/暂停期间系列自动延期，不会在门控中作废。）

2. **🔴 发行方可以冻结甚至销毁池内抵押品。** 全额抵押保证的是"我们不会超发"，**不保证发行方不动手**。`adminBurn` 无暂停检查、无黑名单检查，**无技术手段可防**（§12）。

3. **🔴 买 MEME 必须先有 GME。** 交易对是 MEME/GME，不能直接用 ETH。这是入场摩擦，也是故意的。

4. **权证值不值钱，看的是 MEME 相对 GME，不是 GME 的美元价。** 你的币暴涨时权证归零，这是设计而非故障（§4.3）。

5. **行权会减少你的 MEME 仓位。** 它是"换"不是"领"——烧掉 MEME 才拿得到股票。

6. **首次行权前必须先签一次链上声明，否则 `exercise` 直接 revert。** 只需一次、此后永久有效，但**别留到周五 20:55 才发现**——首次行权是三笔交易（声明、approve、行权），之后是两笔（approve 可长期有效则一笔）。卖出不需要签（§6.3）。

7. **来回交易 6% 税。** 频繁进出会被税吃掉。

8. **卖出 MEME 即停止累积**，但**已累积的不会被没收**——该领的还能领。

9. **归属按时间加权，不是快照。** 领取前一秒买入拿不到任何东西。

10. **merkle root 每周发布一次。** 未发布前无法领取；已铸的权证在 distributor 里，root 补发后可追溯领取。**该系列第一个人领走之后，这一周的 root 就永久冻结了**（`rootFrozen(seriesId)` 链上可读）——在那之前 publisher 可以纠正打错的 root，在那之后谁也改不了。

11. **买来的权证仍需你自己有 MEME 才能行权。** 权证只是权利，支付端要你自备。

12. **`uiMultiplier` 变动时前端显示会跳。** 链上 raw 记账不变，但显示值会变——拆股前后看数字要留意。

### 我们的合约

**尚未部署到 Robinhood Chain。** 八合约部署脚本（含金库身份根、D0 launcher、工厂与身份根名单第 2 格的预留位）已在本地 Anvil 广播、核验并测试；生产部署顺序见
[`spec.zh.md`](./spec.zh.md) §12，**完全不使用 CREATE2**：**WarrantVaultFactory(flapPortal)** →

池子一旦上线，槽位就再也加不进去（决策 39-C / 39-D）。**最后的 target 接线不部署任何金库**（#58）：
金库不可升级，由工厂在每次发射时现部署一只。

**31337 / 31338**；其他 chainId 会在广播或 manifest 晋级前 fail-closed。
🔴 **46630 承载的是 B 段里不依赖 Flap 计价币的那部分**（部署与接线核验、version 0 真实签名、
keeper 的真实时钟节奏）—— **发射 / 金库 / TWAP / 开系列整条在那条链上跑不了**，因为它的 Flap `Portal`
全历史只启用过原生币一个计价币（#64）；那一整条改在 chainId **31337** 的主网分叉上跑，
见 [`design.md`](./design.md) 决策 42。
🔴 这份 allowlist 就是 `DeploySystem.flapPortalFor` 那张「chainId → Flap `Portal`」的表本身：
**允许一条链，等于那条链上有一个 Flap `Portal` 合约**，没有 Portal 的链上这套系统部署成功也只是
一堆永远开不出系列的合约。⚠️ 判据到此为止 —— 「那里有个 Portal」推不出「那里能建币与取价」，

## 12. 风险

| 风险 | 说明 |
|---|---|
| 🔴 **`adminBurn` 可抹掉池内抵押品** | 无暂停/黑名单检查，可从任意地址销毁。**全额抵押防不住**。只能靠多标的分散、事件监控、风险条款明示 |
| 🔴 **发行方可冻结 / 暂停** | `onlyNotBlocked` 硬编码在每条转账路径，查全链共用注册表；另有单币 + 全局双层暂停。缓解：行权干净回滚 + 到期自动延期 |
| 🔴 **merkle publisher 是中心化信任点** | root 由我们计算提交。缓解：算法与复算脚本开源，任何人可独立验证 |
| 🔴 **税可能被平行池绕开** | 历史 BSC MarsCoin 证据显示：**70.4% 成交量**在无税池，实际捕获率 0.90%（名义 3%）。Robinhood Chain 尚缺收税阳性 / 平行池对照，v1 在目标链复核前按保守结构性风险处理；第三方建池仍然**无法由我们的合约修复** |
| 🔴 **签署声明 ≠ 合规已解决** | 它覆盖"谁能收到股票"，**覆盖不了"我们发行了期权"与"我们运营了期权订单簿"**；且自我声明不可强制执行（换地址即绕过）。**最大的风险是把它当成免责金牌** |
| 🟡 **依赖 Flap** | 代币、税收结算、曲线与 Portal 价源在其上。Trigger Service 是我们自己的运营组件；Flap 仍可改平台规则，也可自己做权证 |
| ~~🟡 **Flap Guardian 可升级我们的金库**~~ | ✅ **已消除**（决策 39-A3 / #58）：金库不可升级，Guardian 对它没有任何权限。**在途资金**（≤24h 窗口）本身还在，但它现在只是「本周收入里还没变成权证的那一部分」+ 发行方权限敞口的一小块边角（约池内规模的 0.79%，决策 49 之后 `Pool* = 0.9S/f`），不再是「暴露给一个能换实现的第三方」。量化见 [`r4-in-transit-window.zh.md`](./r4-in-transit-window.zh.md) |
| 🟡 **OTC 市场冷启动** | 无挂单即死市场。前 8 周 taker 免费 + maker 永久免费用于引导 |
| 🟡 **周度到期对被动持有者不友好** | 两周不操作即作废。与生态常态一致（Flap 分红同为 pull 模式） |
| 🟡 **拆股尚未引爆** | 当前 multiplier 几乎全为 1.0。按 raw 单位记账已规避，但需持续监测 `effectiveAt` |
| 🟡 **税收去向可被 Flap 单方面改掉** | Portal 的 `changeMarketWallet` 由 `TAX_GUARDIAN_ROLE` / `DEFAULT_ADMIN_ROLE` 可调，改的是税打给谁；主网上**已经用过三次**（均在别人的代币上）。**已铸权证与池内抵押品不受影响**，受影响的是此后流进金库的收入。合约层无从防御，只能监测（`script/watch-market-wallet.sh`） |
| 🟡 **被拉黑的 creator 分成会滞留** | 10% 分成累计给不可变的 `creator` 地址,`claimCreatorFee` 受 `onlyNotBlocked` 约束。发行方一旦拉黑该地址,这笔累计就再也拉不走 —— 没有 setter、没有找回路径（决策 49-⑧）。**只伤到该 creator 本人**;权证、池内抵押品、每个持有者的份额都不受影响。这是 creator 自己的私钥/资格风险,设计上已计入 |

### 🔴 四层保证不是一回事，必须分开说

| 层 | 靠什么 | 谁能动它 |
|---|---|---|
| **偿付** | **结构保证** —— 抵押品在独立、不可升级、无 admin 提取路径的 ClearingPool 里 | 只有股票发行方（`adminBurn` / 冻结，见上表前两行）。**Flap 碰不到** |
| **发行活性** | **运营保证** —— 系列得有人按期开出来、税得按期存进池子 | 我们自己的运营，外加 Flap 普通 `Portal` 的发射控制与升级风险 |
| **收入** | **平台信任** —— 税打给谁，取决于 Flap 手上的权限 | Flap 的 `changeMarketWallet` |
| **发射能力** | **我们自己的实现 + 平台的两格配置** —— 决策 39 起走普通 `Portal.newTokenV6`，该入口**零注册零授权**且 GME 计价实测可用；✅ 编排层 `WarrantLauncher` 已由 #57 交付（#56 / #58 亦已交付），合约侧不再有阻塞。⚠️ 但平台握着事后关停开关，其中**最便宜的两个**都只要一笔普通交易、不必升级任何合约：`setQuoteTokenConfiguration(GME, {enabled: 0, …})`（GME 不再是计价币）与 `setQuoteTokenCreationDisabled(GME, true)`（仍是计价币，但不许再用它发新币）。🔴 **这是两处不同的存储，任一被拨都发不出新币** —— 实测拨第二个时，第一个读出来还是原值。另有 `halt` / `setBitFlags` 与 Portal 代理升级。**它们只挡「此后能否发新币」，动不了已发代币、已铸权证与池内抵押品**；两个开关我们都盯着（`RobinhoodCurrentCanary::test_gmeIsStillAnEnabledQuoteTokenToday`，跑 latest，风险台账 R16） | **我们 + Flap** —— 发得**出来**靠我们自己的实现，发得**成**靠 Flap 的那两格配置（决策 39 把这一格从「等上游」换成了「自己干」，但换不掉那两格） |

**这四项的强度依次递减，不能混着讲。** "偿付是结构保证"这句话单独拿出来是对的，但**只说这一句就收尾**
会让人以为收入也一样被结构护着 —— 它不是。一次改道不会让任何人手里的权证失去抵押，却会让**此后**
的税不再进我们的金库。第四层与前三层还不同类：它不看护任何已有持有人，而是决定**有没有下一个项目** ——
今天它是**开着的**，而**关不关只取决于 Flap 那两格配置**（上表第四行）。
